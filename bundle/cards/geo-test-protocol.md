# 引用行为实测规程（先测后投与风控红线）

> 能力单元 geo-test-protocol ｜ 来源：《从 SEO 到 GEO》第 6 章（实验设计与风控事件）、第 9 章（先测引用再投入）

## R — 原文

> "每题都在一个全新的独立对话里提问，逐字提问、不改写。"（ch6）
>
> "先测引擎引不引用，再决定投不投入""大约 30 次连续提问后，平台判定违规、触发风控。"（ch9 / ch6）

出处：ch6《实测》实验设计一节与风控复盘；ch9《AI 原生场景》。候选来源：f12, f13, f19, p02, p03, p04, p05, p61, p78。

## I — 解释

两个互补用途共用一套规程：

**用途一：引用行为实测（摸底/复现/复盘）。** 七条纪律：①选题从真实 query 筛，覆盖五种提问动机（对比/症状/方法/信任/选型私域）；②每题开全新独立对话（防上下文串味——面试官不能拿着上一份简历面下一个人）；③逐字提问不改写，真实浏览器/真账号执行；④逐题人工核对引用来源到原始凭证（题少核对细，12 题好过泛泛 100 题）；⑤口径：引用率 = 该题回答是否带出可提取的外部引用来源（二值，记"几/12"，不是引用条数）；各引擎引用呈现位置不同（DeepSeek 内嵌引文、元宝"源"面板、千问接口回抓、文心按"参考资料"站名），跨引擎对比要知道提取难度不一；⑥单次 n=1 只作方向性信号，多次采样（每题 4–5 次）才是统计口径；⑦记录平台成本（登录态、匿名额度）与局限（单账号单日），结论按"方向性 + 定期复核"使用。

**用途二：先测后投（投入筛子）。** 对任何"看起来竞争空白"的卡位：候选 query × 目标引擎做小样本独立采样（书内执行规模 5 次）→ 稳定零引用即红灯（引擎对价值观/方法论类开放题倾向纯模型作答，不翻参考书）→ 有引用再看引的是什么级别信源，你的内容要够得着那个级别，卡位才成立。

**风控红线（排障）**：高频自动化提问约 30 次触发 DeepSeek 风控。单次"一下午 12 题"强度安全；乘以采样次数就越线。三条教训：平台不是爬虫的沙包；自建监测必须限速（分钟级间隔、每日上限，一个都不能少）；持续监测需求优先考虑现成工具（自建隐性成本——账号风险、维护、数据断档——往往高于订阅费）。

**补充口径纪律（GeoLook CN-GEO 数据集实测）**：**API ≠ 网页端，Web ≠ App**——千问 web 与 App 信源重合仅 24.5%，豆包 App 与 web 的字节生态占比差一倍以上；采样时逐端记录采样环境（API/网页/App/账号类型），**跨端结论分开算，不互推**。没有答案原文/截图/环境记录的，不标"真实采样"。

**补充二（GeoLook 采样与归因纪律，MIT）——每条样本标证据等级**：A=人工/浏览器真实样本（有答案原文与来源链接）；B=API 可复现样本（注明是否联网）；C=合成演示或推断；D=待复核（**个人日常账号采样自动降 D**——它测的是"AI 对你的画像"，不能当可见性证据）。采样环境四档不混算：一次性沙箱 / 无痕未登录 / 专用采样 Profile（只用于采样、从不搜自己品牌、关闭记忆与个性化）/ 个人账号。没提到品牌也要照记——"没提到"正是最重要的数据。归因默认写"观察相关"，除非有基线窗口 + 对照 Prompt + 竞品对照。

**补充三（GeoLook cn-platforms/method + GEO Wiki platforms，MIT / CC BY 4.0，2026-09-14 穷尽审查）：**

- **问题类型决定触发检索**：时效/事实/决策类问题更易触发联网检索，模糊问题反而更少触发——问题库选题本身就要"值得让引擎查"。查不到答案时按答案循环顺序排查（从最早步骤查起）：①子查询里没有你的表述→②抓不到未进候选（转 ai-crawler-access）→③内容块不能独立成立未被采信（转 citable-content-spec）→④被采信但未署名。
- **国产平台 API 采样坑**（实测）：千问的 OpenAI 兼容端点即使传搜索参数也**不返回 search_info**，必须走原生端点 + forced_search 才有带 site_name 的来源；火山方舟（豆包）/chat/completions 不支持联网，/responses + web_search 默认 ToolNotOpen、内容插件需控制台单独开通，**开通前后必须丢弃旧样本重设基线**（联网单次约 100 秒 vs 千问约 9 秒）；元宝/百度AI/文心/抖音AI 无公开 API，只能网页/App 人工采样回灌。
- **竞品清单不全会高估名次**：排名指标是相对竞品集合算的，漏掉真实对手名次虚高——首期宁可先跑一轮推荐类采样，从 AI 答案反推真实竞争集。
- **API 度量字段是代理不是界面**：Gemini API 返回 groundingMetadata + webSearchQueries（可直接观测查询扇出）；Perplexity Sonar 返回 citations + search_results（title/url/date/snippet）；Claude cited_text；ChatGPT url_citation 与 sources（通常长于被引集合）——都用来自动化度量，但 API 检索排序与消费端产品不严格对应，只能当最接近的替代。
- **方法论免责五条**（geo-seo-claude，引用外部评分体系时随附）：GEO Score 是诊断工具不保证被引用；权重系作者主观判断非受控研究；schema 验证只查结构不查语义；llms.txt 尚未普及；确定性脚本与 LLM 评审是两类结果。**边缘探针局限**：探针 IP ≠ 真实爬虫 IP，按 IP/rDNS 验证的 WAF 可能拦探针放真爬虫——探针结果标注"可能"而非"确认"。**口径差异**：开发者工具显示渲染后 DOM，检测器读原始响应体——"DevTools 看得到、检测器说没有"不是矛盾。

## A1 — 书中案例

- **元宝 0/5 警示（作者亲历，ch9）**：对"用 DeepSeek 辅导孩子作业靠谱吗"5 次独立采样全部零引用，而同批 12 题元宝整体引用率 81.7%、"小鹅通平替"5/5 全引——0/5 不是偶发是策略。先测引用筛掉了这个"看起来干净"的卡位。
- **DeepSeek 被单测低估（作者亲历，ch6）**：单次 9/12 → 多次采样开启智能搜索后 32/32 全联网；"单次测试会系统性低估它"。若只测一次会把渠道优先级整个排错。

## A2 — 未来触发

- 用户要复测/摸底某引擎的引用行为，或质疑某本书/某篇报告的引用数据。
- 用户问"这个题/这个引擎值不值得投入内容"（先测后投）。
- 用户在做自动化监测/采样脚本，问频率怎么定。
- 语言信号：实测、采样、引用率、测一下 AI 引不引用、复现、风控、限速 / test citation behavior, sampling, rate limit。
- 与相邻能力区分：本卡管"怎么测与测完怎么判"，不管测出来的渠道结论怎么用（geo-channel-map）；日常双周监测的运营节奏归 geo-monitoring-iteration。

## E — 执行步骤

输入契约：query 清单；目标引擎；测试目的（摸底/复现/先测后投）。缺引擎或 query 先询问；自动化脚本须先确认频率约束。

1. **设计**：每题定稿"用户原话"（逐字、不改写）；标注五种动机；确定引擎数与次数（摸底 n=1 可方向性判断；先测后投与统计口径按每题 ≥4–5 次独立采样）。
2. **执行纪律**：每题全新独立对话；逐字提问；人工间隔分钟级并设每日上限；登录态/额度成本先记录。
3. **记录口径**：每题记录"是否带出可提取的外部引用来源"（二值）+ 引用域名清单 + 引用在页面上的呈现位置；不统计引用条数当引用率。
4. **判读**：n=1 → 只回答"引得多/几乎不引/信源构成"方向性问题，禁止精确百分比比较；多次采样 → 统计口径（如 0/5 稳定零引用 = 红灯；如 32/32 全联网 = 修正单测低估）。
5. **先测后投判定**：红灯（稳定零引用）→ 不投入或换引擎；黄灯（引用不稳定）→ 加大样本或先小成本试投；绿灯 → 核对引用源级别是否够得着，再排产。
6. **输出**：测试记录表（query / 引擎 / 次数 / 引用次数 / 引用域名 / 判定）+ 使用声明（快照日期、账号数、局限）。

排障分支：触发风控（提示违规/限流）→ 立即停止自动化提问保账号 → 排查频率（是否连续高频）→ 改限速或转现成工具（GEOBase/新榜智汇）→ 接受"方向性 + 定期复核"而不是加大火力。

## B — 边界

- "5 次"是书内执行规模，无统计依据；可加大样本但必须同步压低频率（红线：约 30 次连续提问触发 DeepSeek 风控，2026-08 观测）。
- 千问、文心的多次采样在原书中也未完成——对这两家的"多次采样层级"结论缺失，只有单次方向性。
- 单账号单日的结论不可写"统计报告"；引擎行为随时段漂移，快照结论定期复核。
- 测试账号会留下真实对话记录，注意账号安全与合规。
