# 教程 01 · 快速上手（5 分钟）

## 这套技能是什么

`geo-playbook` 是从《从 SEO 到 GEO：AI 时代的搜索优化实战手册》蒸馏出的 **13 张能力卡**。装好之后，你的 AI 助手在遇到"内容发哪里、怎么写才被 AI 引用、监测结果怎么办"这类问题时，会自动按书中实测过的方法作答，而不是凭常识即兴。

**一句话理解分工**：你负责问真实问题，技能负责让 AI 助手按实测方法论给出可执行的答案（决策树、清单、体检表），而不是一锅"七条建议"式的鸡汤。

## 第 1 步：选择安装方式（按你的 Agent 对号入座）

| 你的 Agent | 安装方式 |
|---|---|
| **Claude Code / ZCode / WorkBuddy / CodeBuddy** 等支持 Agent Skills 规范的产品 | 把 `geo-playbook/` 目录复制到技能目录：Claude Code 用 `~/.claude/skills/`，ZCode 用 `~/.zcode/skills/`，WorkBuddy/CodeBuddy 按各自文档的技能目录放置。核心是一个含 `SKILL.md` 的文件夹，产品会自动发现 |
| **Codex / Cursor** 等读取 AGENTS.md 的产品 | 把仓库根目录 `AGENTS.md` 的内容放入 `~/.codex/AGENTS.md`（全局）或项目根目录，并把其中的相对路径改成 `geo-playbook/` 的实际位置 |
| **任何能设自定义指令 / 系统提示的 AI 产品** | 打开 `prompts/geo-playbook.prompt.md`，全文粘贴进"自定义指令 / 人设"即可 |

```bash
git clone https://github.com/88lin/geo-book-skill.git
# Claude Code 示例：
mkdir -p ~/.claude/skills && cp -r geo-book-skill/geo-playbook ~/.claude/skills/
# ZCode 示例：
mkdir -p ~/.zcode/skills && cp -r geo-book-skill/geo-playbook ~/.zcode/skills/
```

重开会话即生效。

## 第 2 步：验证装好了（3 个验证 prompt）

新开会话后，随便挑一条问：

1. **"我们是做仓储管理系统的，内容应该先发到哪些平台？"**
   → 应触发渠道决策树：先反问决策人画像（或要求提供），再按"定引擎→看生态→按题型→定形态"四步给分工表，并提醒行业外推需实测。
2. **"我写了篇文章结论埋在第三段，帮我改得更容易被 AI 引用"**
   → 应触发四条硬指标体检：逐项 pass/fail + 改写，而不是直接重写一遍。
3. **"我们要不要屏蔽 GPTBot？"**
   → 应触发 AI 爬虫卡：按"训练/检索/用户触发"三类分别决策，明确警告"全部 Disallow = 立即失去被引机会"。

三条都对，安装完成。

## 第 3 步：理解它怎么工作（路由逻辑）

技能内部是一个"路由表 → 能力卡"的两级结构：

```
你的问题 → SKILL.md 路由表（按意图匹配）→ 加载 1 张能力卡 → 按卡内步骤执行
```

13 张卡各自独立成篇，包含原文依据（R）、方法解释（I）、书中案例（A1）、触发场景（A2）、执行步骤与输入输出契约（E）、边界与反例（B）。**你不需要记住卡名**——描述问题即可；想强制指定时可以点名："用 geo-channel-map 帮我分析"。

## 常见问题

- **没触发 / 触发了别的技能？** 在问题里带上意图关键词（发哪里、哪个引擎、怎么写才被引用、监测、智商税、llms.txt），或直接点名能力卡。
- **它反问我一堆问题是不是啰嗦？** 这是设计行为：卡内输入契约要求"缺决策人画像/目标 query/品牌立场先询问，不猜值"。把信息一次给齐，答案会直接得多。
- **数字能直接引用吗？** 所有引擎信源数字是 2026-08-05 快照或第三方数据集口径，按"方向性"使用——写给内部决策可以，写成对外统计报告不行。
- **想看完整方法论？** 读 `docs/DIGEST.md`（约 8000 字精华）或原书：[JingHao-Leon/geo-book](https://github.com/JingHao-Leon/geo-book)。
