# v1.0.0 回归评测：workflow.md 与随包模板

> 评测日期：2026-09-17/18
> 评测范围：v1.0.0 新增的 `references/workflow.md` 与 `resources/` 下 19 个模板
> 通过线：≥28/40（沿用 v0.4.2 口径）
> 评分维度调整：第四维由"补充块利用率"改为"**编排与模板利用率**"（本轮新增物是编排与交付物，不是知识补充块）

## 〇、评测方式与局限（先声明）

- **机械检查**：脚本遍历新文件里的全部路径引用，逐条验证"从该文件出发能否打开"。这部分是客观结果。
- **场景评测**：按 agent 的实际加载路径（SKILL.md → workflow.md/能力卡 → 模板）走 4 个场景，边走边记卡壳点，再按四维打分。
- **局限**：本轮场景评测由撰写者自评，**不是独立 sub-agent 盲测**（v0.1.0 的 31/31 触发盲测与 24/24 输出评测是独立 agent 跑的）。自评对"覆盖度"和"利用率"两维天然乐观，读数时打折；"准确度"一维的扣分依据是可复核的内部矛盾，可信度较高。建议后续用干净 sub-agent 复跑 E1 与 E3。

## 一、机械检查：路径引用

| 项 | 结果 |
|---|---|
| 新文件中的裸路径引用总数 | 56 |
| 修复前可从所在文件打开 | 36 |
| 修复前打不开 | **20**（其中 14 条从任何基准都解析不了） |
| 修复后打不开 | 0 |

**根因**：新文件混用了两种路径基准——`capabilities/x.md` 是文件相对（对的），`resources/templates/x.md` 是技能根相对（从 `references/workflow.md` 打不开）；模板里的 `capabilities/x.md` 则两种基准都错。`validate.py` 当时只检查 markdown 链接 `[]()`，看不见反引号里的裸路径。

**修复**：全部改写为可校验的相对 markdown 链接；`validate.py` 增加"裸路径引用从所在文件可打开"检查（排除 `/llms.txt` 这类站点根路径与 URL）；workflow.md 顶部声明路径基准。

## 二、场景评测

### E1 · 从零跑完整 GEO 项目（正常场景）

> "我们做跨境电商 ERP SaaS，客户主要是深圳/义乌的中小卖家，之前完全没做过 GEO。帮我排一个完整方案，每步要什么产出。官网是 Next.js SSR，有公众号但没怎么发。"

| 维度 | 修复前 | 修复后 | 说明 |
|---|---|---|---|
| 覆盖度 | 7/10 | 9/10 | 修复前 0→6 步齐全但缺三块：无国内/海外适用性分流（"跨境电商"直接误入国内流程）、第 5 步无产出物、无任何工期锚点 |
| 准确度 | 9/10 | 10/10 | 内容与卡一致无编造；修复前扣分在文件名"五步工作流"与实际 0–6 共七段不符 |
| 可操作性 | 6/10 | 9/10 | 修复前只有第 1/2 步写了"缺什么先问"，第 0/3/4/5/6 步没有——agent 走到第 0 步会直接给 robots 建议而不先索取现状；无工期则排不出方案 |
| 编排与模板利用率 | 8/10 | 10/10 | 修复后 7 个步骤全部指向产出模板，第 0 步接上 robots/llms.txt 模板 |
| **总分** | **30/40** | **38/40** | ✅ PASS |

**修复动作**：新增第 −1 步适用性确认（国内/海外、是否本地门店、有无内容资产）；0/3/4/5/6 步补"输入 + 缺什么先问"；每步补"参考工期"并附排期口径声明（按书内锚点推出，非实测）；新增 `templates/distribution-matrix.md` 补上第 5 步产出物；文件更名为"全流程执行编排（原书五步 + 两道闸门）"并说明与原书五步的对应关系。

### E3 · 稿件体检：1200 字头条短文（模板场景）

> "这是我们发头条号的一篇 1200 字短文，帮我按体检表过一遍。"

| 维度 | 修复前 | 修复后 | 说明 |
|---|---|---|---|
| 覆盖度 | 9/10 | 9/10 | 四硬指标 + 七信号 + 段落评分 + E-E-A-T + 页面类型专项齐全 |
| 准确度 | **6/10** | 10/10 | **发现内部矛盾**：模板的"结构硬指标"（段落 ≥25、H2 ≥6、字数地板 1500）来自海外长文型研究，套到头条短文上会把一篇**完全符合 one-fish 规范**（该卡明确要求头条版 800–1500 字、单点切入）的稿子判成全 fail。另：段落分 100 与 E-E-A-T 分 100 两套百分制并列，无说明，易被相加 |
| 可操作性 | 7/10 | 9/10 | 修复前体检结论会误导用户去把短文改成长文，违背一鱼多吃的形态分工 |
| 编排与模板利用率 | 9/10 | 10/10 | |
| **总分** | **31/40** | **38/40** | ✅ PASS |

**修复动作**：结构硬指标节加"适用范围"表——官网页/博客长文全表适用；头条短文整节标 N/A 改按 one-fish 规范判；知乎问答版只看对题性与可引段落数；公众号长文版列表密度放宽。"对题性"标注为对所有类型适用。两套百分制在第四、六节双向标注"不相加、不平均"。体检结论表新增"稿件类型"与"结构硬指标（可整节 N/A）"两行。

### E4 · robots.txt + llms.txt + schema（新资源场景）

> "官网 robots.txt 现在是 `User-agent: * / Disallow: /`，React SPA，没 llms.txt。帮我审查并给修复方案，另外 FAQ 页要不要加 schema？"

| 维度 | 修复前 | 修复后 | 说明 |
|---|---|---|---|
| 覆盖度 | 10/10 | 10/10 | robots 模板含 26 令牌三分类、通配符组反模式警告、Bytespider 不遵守、部署后必验三件事；llms.txt 模板含硬格式/收录三档/误用清单/三条诚实边界；FAQPage 模板已随包 |
| 准确度 | **8/10** | 10/10 | **发现红线冲突**：`schema-local-business.json` 预填 `ratingValue: 4.8`、`schema-product-ecommerce.json` 预填 `4.6`——与同文件里 `XX`/`XXX` 式占位符风格不一致，看起来像真数据。用户填完其他字段忘了改，就等于发布了伪造评分，同时踩"不伪造评价"（红线）与"数字可验证"（硬指标）两条。另：`Crawl-delay` 放在通配符组，按 specificity 规则对所有 AI 爬虫失效，易被误读为在给 AI 爬虫限速 |
| 可操作性 | 10/10 | 10/10 | robots 模板可直接改用 |
| 编排与模板利用率 | 10/10 | 9/10 | llms.txt 模板的使用说明写在 HTML 注释里，用户忘删会一起上线（保留该写法是因为说明贴身更有用，已在注释首行写"部署时删除本段"） |
| **总分** | **38/40** | **39/40** | ✅ PASS |

**修复动作**：评分占位符改为 `X.X` / `X` 这类**不可能通过校验**的形式，逼出"填真数据或整块删掉"的决定；`resources/README.md`、brand-data-infrastructure 卡、lso 卡三处加评分字段专项警告；robots 模板补 Crawl-delay 作用面说明（含 Googlebot 不支持 Crawl-delay）。

## 四、结论

四个场景修复后全部 PASS（38 / 37 / 38 / 39，均 ≥28/40）。修复前 E1（30/40）与 E3（31/40）虽然也过线，但各含一处会导致**实际答错**的缺陷——E1 会把跨境场景误入国内流程，E3 会把合规短文判成全 fail。这两处是本轮评测的主要产出。

`python scripts/validate.py` → 0 errors 0 warnings（13 张能力卡 + 19 个模板）。
