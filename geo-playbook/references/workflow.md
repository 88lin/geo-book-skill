# GEO 全流程执行编排（原书五步 + 两道闸门）

> 用途：当任务是"从零跑一个 GEO 项目""第一步该做什么""帮我排一个完整方案"这类跨卡任务时读本文件，再按每步指示加载对应能力卡。
> 单点问题（只问渠道、只改一篇稿）不需要读本文件，直接按 SKILL.md 路由表加载一张卡。
> 本文件中的路径相对于本文件所在目录（技能的 `references/`）。
>
> **与原书五步的对应关系**：原书方法论是 query 研究 → 渠道分工 → 内容生产 → 一鱼多吃分发 → 监测迭代（对应下面第 1/2/4/5/6 步）。本文件在前面加了**第 −1 步适用性确认**与**第 0 步可访问性体检**（补自 GEO Wiki 的四层依赖模型，原书未覆盖），在中间插入**第 3 步先测后投闸门**（原书 ch9 的投入纪律，本文件把它提为独立关卡）。

## 第 −1 步 · 适用性确认（问完再开工，三个问题）

开工前必须先确认下面三件事，**答案不同流程完全不同**，猜错会让整套方案作废：

| 要确认的 | 为什么 | 答案的影响 |
|---|---|---|
| **目标市场是国内还是海外** | "跨境电商""出海 SaaS""外贸"这类词容易被误当成国内场景 | 面向**国内用户**（哪怕业务是跨境）→ 走本流程；面向**海外买家/海外引擎**（ChatGPT/Perplexity/Gemini/Google AIO）→ 超出本包范围，只能给机制层对照，实操要另找资料。两套市场两套打法，同一查询仅约 11% 域名被 ChatGPT 与 Google AIO 同时引用，结果不可互推 |
| **是不是本地门店生意** | 本地生意的竞争范围是商圈不是全网 | 是 → 直接走 `capabilities/lso-local-playbook.md` 的五步闭环，不走本流程 |
| **现在有没有内容资产** | 决定从哪一步切入 | 完全没有 → 从第 0 步顺序走；已有一批内容但没被引用 → 先做第 4 步体检，形态合格再回第 2 步查渠道（见文末快捷路径表） |

另外记下两个会反复用到的输入，缺了就问，**不要猜**：**决策人是谁**（不是"用户是谁"）、**行业是否在已验证行业内**（原书实测只覆盖广告电商与教育两行业，其他行业的"决策人-引擎"映射是外推）。

## 依赖顺序（为什么不能乱序）

四层依赖模型（访问 → 定向 → 理解 → 可引用，见 ai-crawler-access）决定了修复与投入顺序：**上游层失败时，下游所有优化在引擎侧不可见**。所以"官网被 AI 抓不到"必须先于"内容怎么写"解决；同理"渠道选错"先于"内容打磨"（七分渠道三分内容）。

```
第 0 步 可访问性体检 ──┐
                       ├─→ 第 1 步 query 研究 → 第 2 步 渠道分工 → 第 3 步 先测后投闸门
长期底座 数据基建 ─────┘                                                    │
                                                                            ↓
        第 6 步 监测迭代 ←── 第 5 步 一鱼多吃分发 ←── 第 4 步 内容生产 ──────┘
                │
                └──→ 回灌第 1/2/4 步（三分支动作）
```

## 第 0 步 · 可访问性体检（技术侧，可与第 1 步并行）

- **入口卡**：`capabilities/ai-crawler-access.md`
- **输入**：站点 robots.txt 现状（全文）、渲染方式（SSR/SSG/CSR）、是否已有 sitemap.xml 与 llms.txt。**缺 robots.txt 全文先索取，不按猜测给规则**。
- **做什么**：审计四状态（想放行谁 → robots.txt 声明了什么 → 真实请求返回什么 → 日志里谁来过）；排查三个国内高频致命点：SPA 空壳页、WAF/CDN 按 UA 拦截、X-Robots-Tag 头级 noindex。站点已是 SSR/SSG 时"SPA 空壳"一项标 N/A，但 WAF-UA 与响应头两项仍要实测。
- **产出**：robots.txt 修改建议（模板 [resources/robots-ai-crawlers.txt](../resources/robots-ai-crawlers.txt)）+ 可读性问题清单 + 可选的 [resources/llms.txt.template](../resources/llms.txt.template)。
- **参考工期**：robots.txt 改写 ≤1 天；llms.txt 部署 ≤1 天；SPA 空壳整改（需要上 SSR/预渲染）属研发排期，按各自技术栈估。
- **判停**：检索类爬虫在 robots.txt 与真实响应两层都被放行前，不要把预算投向内容生产——内容进不了候选集。
- **可降级的情况**：目标渠道只有第三方内容平台（公众号/头条/百家号/抖音）、暂不指望官网被引时，本步降为"顺手做"；但官网仍是**事实源**（决定 AI 描述你时口径对不对），不是可以不管。

## 第 1 步 · query 研究与分级

- **入口卡**：`capabilities/geo-query-research.md`
- **输入**：行业/产品领域、1–2 个真实语料来源、每月产能约束。**语料来源缺失时先问，不编 query 凑数**。
- **做什么**：从真实语料捞用户原话 → 三维标注（决策阶段×引用性×竞争度）→ 定级 easy_win / target / skip。
- **产出**：query 清单表（模板 [resources/templates/query-grading.md](../resources/templates/query-grading.md)）。
- **参考工期**：捞词与标注是人工活，几十条量级通常 2–5 个工作日；标注前两个人先对齐口径。
- **判停**：某条 easy_win 的竞争度拿不准 → 标注后转第 3 步实测，不在纸面上硬判。

## 第 2 步 · 渠道分工

- **入口卡**：`capabilities/geo-channel-map.md`
- **输入**：第 1 步的 query 清单 + 决策人画像（行业、决策人是谁、活跃场景）。**缺"决策人是谁"先问，不猜**。
- **做什么**：定主攻引擎（按决策人动线，不按平台名气）→ 按引擎生态定渠道 → 按题型修正 → 每条 query 定 ≥2 个形态。
- **产出**：引擎 × 渠道 × 形态分工表（模板 [resources/templates/channel-matrix.md](../resources/templates/channel-matrix.md)）。
- **参考工期**：1–2 天出表；但缺失的渠道基建（如没有公众号矩阵）是独立工期——元宝这条路没有公众号就是断的，属刚性约束不是优化项。
- **判停**：目标行业不在已验证行业（广告电商、教育）内 → 不套用映射，转第 3 步小样本实测再定渠道。

## 第 3 步 · 先测后投闸门（投入前的第一道筛子）

- **入口卡**：`capabilities/geo-test-protocol.md`
- **输入**：候选 query 清单（用户原话逐字）、目标引擎、采样环境（沙箱/无痕/专用 Profile/个人账号）。**自动化脚本须先确认频率约束**；个人日常账号采样自动降为 D 级证据，不能当可见性证据用。
- **做什么**：候选 query × 目标引擎做小样本独立采样（每题独立新对话、逐字提问、二值引用口径，5 次起）。
- **判读**：红灯（稳定零引用）→ 不投入或换引擎；黄灯（引用不稳定）→ 加样本或小成本试投；绿灯 → 核对引用源级别够不够得着，再排产。
- **产出**：测试记录表（模板 [resources/templates/geo-test-log.md](../resources/templates/geo-test-log.md)）+ 使用声明（快照日期、账号数、局限）。
- **参考工期**：书内执行强度"一下午 12 题"单次是安全的；乘以 5 次采样就必须拆到多天，配分钟级间隔与每日上限。
- **红线**：自动化提问分钟级间隔 + 每日上限（约 30 次连续提问触发 DeepSeek 风控）。持续监测需求优先用现成工具，不自建脚本硬跑。

## 第 4 步 · 内容生产

- **入口卡**：先 `capabilities/golden-question-formulas.md`（判题型给骨架），再 `capabilities/citable-content-spec.md`（硬指标验收）。
- **分支**：负面/信任类 query → 加读 `capabilities/negative-semantic-occupy.md`；视频形态 → 加读 `capabilities/vso-video-optimization.md`；官网答案页 → 加读 `capabilities/aeo-answer-optimization.md`。
- **输入**：目标 query 原话、品牌立场（当事方 / 中立测评方 / 被质疑方）、可公开的真实事实（价格构成、资质、可验证案例）。**缺 query 原话或品牌立场先问；产品参数与价格不代填**。
- **做什么**：按症状/对比/信任三类套内容公式产出骨架 → 用四条硬指标 + 七个结构信号逐条体检改写。
- **产出**：稿件骨架 + 体检表（模板 [resources/templates/citable-content-checklist.md](../resources/templates/citable-content-checklist.md)）+ 改写稿。
- **参考工期**：产能口径是"一个月做透 10 条 easy_win 胜过铺 100 条平庸稿"——按这个反推单条的投入，不要按篇数排产。
- **完成标准**：四条硬指标全部 pass（结论前置 40–60 字、对比表 ≥5 维度、价格带日期且为文字页、数字可验证）。

## 第 5 步 · 一鱼多吃分发

- **入口卡**：`capabilities/one-fish-multi-platform.md`
- **输入**：一份已完成的底稿（含核心事实、数据、对比结论）+ 第 2 步的目标引擎清单。**底稿没有明确核心事实时先停下确认，不硬改**。
- **做什么**：把底稿压成"结论+数据+适用边界"原料清单（三版共用保口径一致）→ 逐版改造知乎问答版/公众号长文版/头条短文版 + 官网事实页。
- **产出**：各平台版本文件 + 分发对照表（模板 [resources/templates/distribution-matrix.md](../resources/templates/distribution-matrix.md)）。
- **参考工期**：一稿三版是改写不是复制，按"再写一遍"估工，不要按"复制粘贴"估。
- **红线**：改写不是复制粘贴——原样多平台铺发是低质 AIGC 的识别特征，会被降权。三版之间不允许出现连续相同段落。
- **业态分支**：本地商户 → `capabilities/lso-local-playbook.md`（五步执行是它自己的完整闭环，不走本步）。

## 第 6 步 · 监测迭代

- **入口卡**：`capabilities/geo-monitoring-iteration.md`
- **输入**：第 1 步的 query 清单、已发布内容与平台映射、监测资源约束（有没有研发、预算）、竞品集合。**缺 query 清单先回第 1 步**；竞品清单不全会让名次虚高。
- **周期**：两周一个周期（引擎信源库更新比搜索引擎慢，天天盯只制造焦虑）。买家意图题（价格/推荐/比较/替代）约 20 条可以每周轻量复查，全量题库留给每期正式采样。
- **做什么**：建基线 → 选工具路径（免费工具 → SaaS → 仅当成本与灵活度都成瓶颈才自建）→ 定期采样 → 执行三分支动作。
- **三分支回灌**：被引 → 固化形态横向复制到同 cluster（回第 4 步）；竞品被引 → 拆竞品那篇针对性改写（回第 4 步）；整题无引用 → 先查题型选错没有（回第 1 步）再查渠道铺错没有（回第 2 步）。
- **产出**：双周迭代记录（模板 [resources/templates/monitoring-log.md](../resources/templates/monitoring-log.md)）。
- **参考工期**：周检轻量节奏约半小时/引擎；变更发布后按风险分级复核——需观察类 7/14/28 天各一次，高风险类（robots/WAF/noindex/渲染架构）发布后立即重跑体检。
- **度量口径**：被引用率、品牌描述倾向、对比站位——不看排名与 UV。

## 长期底座（与五步并行，不排在时间线上）

- `capabilities/brand-data-infrastructure.md`：本周建官方事实页 → 三个月 Schema 结构化 + 全渠道口径对齐 → 按需评估 API 化。结构化数据模板见 [resources/README.md](../resources/README.md)。注意定位——官网是**事实源**（让 AI 描述你时口径正确）而非引用源（全库引用仅占 1.37%）。
- `capabilities/aeo-answer-optimization.md`：单页的机器可读形态（结构化问答 / FAQPage schema / Speakable）。

## 时间预期与判停

- **排期口径声明**：原书没有给完整项目的工期表。上面各步的"参考工期"是按书内已有锚点（事实页"本周"、Schema"三个月"、监测"两周一周期"、llms.txt"≤1 天"、"一下午 12 题"、"一个月做透 10 条"）推出的参考节奏，**不是实测数据**，给客户排期时按自己团队产能校准。
- GEO 改动完整见效通常 **4–8 周**（平台需重新索引）；实时检索型引擎数小时到数天可见变化但波动大。不要在两周内用"没效果"下结论。
- 整体引用覆盖率约 50.4%（第三方 9786 题口径）——近一半回答零引用是常态，目标是在"有引用的那一半"里占位，不是把覆盖率拉到 100%。
- 点击 AI 摘要内部链接的比例约 1%——价值在"被说出"不在"被点开"，别拿官网 UV 当 GEO 的验收指标。
- **全流程判停**：第 0/2/3 步任一给出红灯而用户仍要求直接铺量时，说明代价（进不了候选集 / 渠道错配零引用 / 引擎稳定不联网）并给替代路径，不顺着执行。

## 不同起点的快捷路径

| 用户处境 | 跳到 |
|---|---|
| "已经有一批内容了，为什么没被引用" | 第 4 步体检（citable-content-spec）→ 若形态合格再回第 2 步查渠道 |
| "只想解决一个具体问题" | 不走本流程，按 SKILL.md 路由表加载单卡 |
| "官网刚上线，什么都没有" | 第 0 步 → 长期底座（brand-data-infrastructure）→ 第 1 步 |
| "被 AI 说成智商税了" | negative-semantic-occupy 单卡，必要时回第 2 步定渠道 |
| "本地门店" | lso-local-playbook 单卡（自带五步闭环） |
| "做海外市场 / 打 ChatGPT 和 Perplexity" | 超出本包范围——只给机制层对照数据并说明国内外不可互推，不套国内打法 |
| "要给客户出一份 GEO 方案" | 完整走 −1→6，每步产出物用 `../resources/templates/` 下的表格 |
